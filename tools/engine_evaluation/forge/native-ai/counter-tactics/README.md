## Scope

This Forge-derived CounterAi correction scans actual optional opponent stack
targets instead of only the top item, preserving per-candidate native targeting,
AITgts and ConditionWouldDestroy checks. It prefers a narrowly recognized critical
target; otherwise it keeps native stack ordering. Existing mandatory/trigger
targeting and payment methods remain byte-identical to upstream.

The selected-target override bypasses only the final discretionary preference
veto. Existing random draws, category flags, earlier refusals and outer native
legality/cost admission remain. Literal targeted damage requires observer source
visibility, current native player-target legality, a simple leaf, no infect or
source lifelink, and the native damage estimate. Visible active LifeReduced
replacements with applicable or unresolved conditions withhold the override.
Ordinary counter policy remains available; uncertainty is not a forced decline.

Only Battlefield/Graveyard/Exile/Command/Stack are visited for that new replacement
query, with BOTH CardView guards before replacement collection access. Native
canReplace and requirementsCheck are called only after their bounded public
dependency admission. See SOURCE-PRESERVATION.json for the exact contract.
There is no global replacement collector, replacement execution, named-card rule,
RNG reset or forced AI cast. Native transitive damage/target/infect forecasts are
not globally observer-fenced or complete. Payment backlash and broader replacement
interactions remain qualification limits, not guaranteed-survival claims.

registered/physical inventories and canonical programs are used. Diagnostics
follow the first ordinary Default chooser callback. Original Java bytes and
declarations are pinned; seeds are declared, not searched.

- Counter16: eight direct lethal-Bolt cases, two lower-stack Shusher cases, and
  six unfunded/uncounterable/friendly controls. A post-decline manual lower-stack
  action is a trusted legal control, NEVER an AI pass. Baseline strict RED stays RED.
- Gilded2: genuine paid response makes an already-selected Bolt target illegal.
  Candidate helper must not call it critical. The recorded ordinary choice has

  It is not an ordinary-choice decline golden.

## Portable Runner

Requires Python 3.9+, Linux bwrap/timeout/findmnt/ps, and the pinned cached native
base/JDK/dependencies. Install nothing. The product class is supplied in the
candidate prefix; this runner compiles ONLY the three unchanged audit sources.

```sh
python3 run.py /path/to/base/BUILD-IDENTITY.json /path/to/E5/candidate /local/fresh-evidence /path/to/E6/candidate3
# Baseline observation; policy RED is a nonzero exit, not inverted into PASS:
python3 run.py /path/to/base/BUILD-IDENTITY.json /path/to/E5/candidate /local/fresh-baseline-evidence
```

Admission requires exact E5 9-source/16-class and candidate3 10-source/17-class
manifests and physical inventories. All prior nine sources/sixteen classes must
remain unchanged. Candidate source fa7815, class baf7d165 and content db05b703 are
exact, not interchangeable. The qualified base identity and 59,971 resource pins
are checked before/end. Actual CounterAi load origin and observed override
origins are recorded per JVM; unused classes are not force-loaded.

Compilation plus all native mains share a 300-second budget, with a five-second
termination grace. Heap is 1500 MiB, ActiveProcessorCount=1. One owned JVM runs
at a time; at most one other JVM is admitted. Input roots are read-only in bwrap,
with a fresh network namespace and only owned output subdirectories writable.
No application/database modules are imported. This is NOT native SQL-denial
instrumentation and makes no global SQL/security/resource-quota claim.

Each child's native exit, logs, class-load receipts and summary are retained.
Native errors take precedence over policy RED; otherwise the first nonzero
policy exit is propagated via SystemExit. Runner integrity errors exit 2 and
are not relabeled engine bugs. Only aggregate counts print to the terminal.
Hands, RNG state and native logs remain in the fresh PRIVATE local evidence
directory. Archive completed evidence under the project's verified writable NFS
share; never execute SQLite on NFS or publish those private outputs.
