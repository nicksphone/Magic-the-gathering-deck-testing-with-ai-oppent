# Explicit Graveyard Self Activation

Scoped product over immutable `7f1fa9c940ac01b06e3f28194efa2e0352160ea3`.
Two full public-bulk canonical families: Reassembling Skeleton returns itself
to the battlefield tapped; Sanitarium Skeleton returns itself to its owner's
hand. Names identify fixtures, not production branches. No SQL/HTTP qualification.

The complete activated body must match the closed self-return grammar. Unknown
compound/timing suffixes, including parenthesized restrictions, remain unoffered.
Original ability indices survive rejected candidates. This does not prove that
unoffered graveyard cards are inert or that every layout/activation is supported.

Graveyard activation requires exact owner, zone and owner-list membership, not a
stale battlefield controller. The action is non-targeting. Its internally sealed
`__self_graveyard_return` discriminator is generated by the compiler; clients do
not select another graveyard object. Existing cost/timing/admission checks remain.

The activation branch retains its existing pre-payment source reference. It binds
that reference to the destination handler's existing `__graveyard_reference`:
hand uses `zone_sequence`, battlefield uses `zone_change_sequence`. A same-ID new
object cannot be moved by the old frame. Paid costs stay paid on countering or an
invalid source reference. Stack/schema/AI/cost/events providers are unchanged.

The battlefield return handler applies explicit `tapped=True` after the actual
zone move and before counters and ETB receipts. The existing pending-entry
payload preserves that instruction if native counter preparation pauses.
