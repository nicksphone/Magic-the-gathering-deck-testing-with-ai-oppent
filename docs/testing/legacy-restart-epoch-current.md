# Legacy Restart Epoch Checks

This is a test-support correction, not a change to production ownership,
capacity, persistence, gameplay or startup deadlines. The guarded legacy audit
retains its complete raw logical-SQL hash and exposes a separately named
restart-stable fingerprint. That fingerprint replaces only the current owner's
epoch cell in the single, fully bound seven-column capacity row. All other SQL,
schema, rows, timestamps and capacity values remain hash-significant.

Default `stable()` comparisons still retain raw hashes, epochs and full ledgers.
Across a real restart, the test additionally requires different actual child
PIDs, normal termination of the saved child, different owner epochs and raw
hashes, equal full canonical SQL fingerprints, and type-aware equality of all
remaining state, controller, revision and capacity operands. Same-epoch
rejection and normalization checks continue to compare raw audit identity.

Exactly three original restart-test operands change. Every other original
gameplay, privacy, stale-revision and rejection assertion remains. The sibling
authorization tests preserve their historical preimage JSON, recognize only
those declared substitutions, pin the pair helper and actual process bindings,
and record evolved inherited sources in a separate reviewed ledger. They do
not silently refresh expected hashes from ambient files.

private on RCHFiles. No protected CI input is published. The legacy fixture's
closure proof is process-reaped only, not a zero-owner/zero-checkout receipt.

uses the pinned real audit producer and complete-dump fingerprints.

Independent reviews cover the epoch fingerprint and exact 16-case adaptation.
The separately reviewed sibling source/authentication delta is also cleared
within its pinned scope. Neither review substitutes for the parent's real

Full protected backend CI, native deployment, measured AI strength and the
