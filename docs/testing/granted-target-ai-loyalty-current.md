## Source And Behavior

The surgical composition over `8b56b3a` integrates eight generic granted-target
production paths, two AI paths and the loyalty announcement UI. The original
tests are preserved; the new audit packages and loyalty checks are runnable
repository inputs, not only archived temporary tests. No dependency, seed,
database, API schema, deck classifier, style or AI weight is changed.

The bounded complete quoted static instruction grants recipient-bound triggers.
Announced target occurrences retain their source/object references, compiled
instruction and quota. Publication commits the quota before callbacks. Genuine
copy paths, including no-choice copies, capture and mark before publication;
repeat marking is idempotent. Unknown/unqualified capture is distinct from an
authoritative empty result; malformed packets reject rather than silently
falling back to a current-state lookup. Actual copied StackItems and exact quota
deltas are asserted in the strengthened producer checks.

AI attachment projection now evaluates a legal already-attached equip target
and completes the underlying attachment. The count-only acquisition forecast
requires a published typed receipt, matching occurrence/controller/instruction
and committed quota. It is capped by public library size and uses the existing
card-count valuation. It never resolves the opaque reveal into a guessed card,
land, mana or permission. Spent slots do not provide another payoff. This is an
attachment-projection repair plus a shared AI-only simulation frontier: imminent
opaque conditional resolution returns uncertainty before mutation across the
actual settlement, rollout, reply and strategic callers. First priority passes,
actual offered responses and known canonical resolution remain executable.
Published, deduplicated acquisition counts provide the existing 0.9 card-count
valuation only at an unknown settlement horizon; they never become hand cards.
This is not a universal proof about every future nested effect or planning path.

The actual Battlefield loyalty handlers consume public permanent candidates
and explicit X drafts. They allow a deliberate land/decline choice, deduplicate
target IDs and reject negative, fractional or excessive negative-X drafts.
Twenty both-seat compiled-handler submissions replay through checked canonical
backend actions and snapshots. They are not mounted DOM/browser episodes.
