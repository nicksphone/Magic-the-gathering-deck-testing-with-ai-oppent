# Native AI Knowledge Boundary

Forge's card rules and Default AI are the work of the Forge Team/Card-Forge
contributors. The isolated corrections below retain their GPL notices and use
revision `61e9442c433711a82258daca3236f936a1d6f70e`. They are not deployed to the
live application, an expert-policy claim, or a completed fairness audit.

## Confirmed Identity Leak And Correction

The ordinary native attack heuristic asked whether the defender could prevent
combat damage. Its external-zone inventory used the defender's permissions,
including an owner-private library top under Experimental Frenzy. Concealed Fog
versus Forest changed the real attack target despite equal actor views. The
original eight paired checks produced two strict failures and six passes.

The [one-body correction](../../tools/engine_evaluation/forge/native-ai/README.md)
checks the actual observing AI's native visibility before inspecting an unknown
card's abilities or costs. Existing legitimate revealed-card memory and
owner-side evaluation remain. The unchanged original eight and twelve added
public/known/private controls all pass on that candidate, in both seats.
These are controlled positions, not twenty full games.

A distinct content-pinned runtime profile prepends only the corrected
`ComputerUtil.class` to the qualified classpath. It retains the existing native
process sandbox, card rules, Default policy and input/game limits. The old build
ID is not reused. The app source is the published `74356fcf`, not the separate

- Reload retained the same session/current question. Wrong-capability, stale

- The actual loaded override origin and bytes, supporting adapter origins and
  before/end app-source pins were independently checked. All owned game/app
  processes ended and the local database closed cleanly.
- A real checkpoint still loads under its original build and rejects the changed
  AI build before reconstruction. A positive cold save on this new profile has
  **not** been qualified.

This is one operational game on the identity-only candidate, not both-seat
qualification on that build, a strength comparison or proof of no hidden inputs.
Private hands, RNG/state streams, screenshots and database evidence remain in
protected NFS archives, not public fixtures.

## Affordability Leak And Separate Correction

The [unchanged follow-up](../../tools/engine_evaluation/forge/ai-boundary/hidden-mana-followup/README.md)
reproduces a second channel on both upstream and the identity-only candidate:
two strict failures and four passing controls on each. A legitimately remembered
Fog is known, but the native affordability search reads the defender's unknown
hand mana sources. Concealed Elvish Spirit Guide versus Forest changes the
heuristic even though the observer's public view and Fog memory are equal.

The [separate three-source correction](../../tools/engine_evaluation/forge/native-ai/known-mana/README.md)
threads an explicit per-query known-card predicate through the native cost/mana
search. Unknown source hosts reject before their abilities are inspected, and
the three direct hand-preference readers filter before consuming identities.
Legacy unrestricted owner-side APIs still use the native payment algorithm.
No unknown card is moved, mana solver substituted or RNG reset used.

The unchanged original twenty checks and six follow-up checks, plus four new
remembered-source/owner-payment controls, pass: **30 ordinary passes, zero
failures/errors**. On the identity-only baseline the same checks gave two strict
failures and 28 passes. Four actual owner-side paid casts and two unpayable
attempts retain complete canonical state/RNG equality with that baseline.

A separate parent rebuild reproduced all three modified sources and four class
payloads, including `ComputerUtilCost$1`, byte-for-byte. The parent independently
ran all thirty checks successfully against that rebuild. These are controlled
native positions, not thirty games. Source filtering does not certify arbitrary
additional-cost, conditional/global-source, replacement or held-piece hooks.

The candidate content ID is `74e0cc8af0915195b8a0a353439847206997c3c0f9ba9b520731ce3708ae8d9b`.
Its parent-composed app profile has a different build identity from both the
base and identity-only candidates. Application qualification on that exact
profile is separate from the historical UI run above.

### Direct-API Guard And Cleanup UI Finding

Review found one direct-overload edge after the source filter: a retained
preference could index an empty list. A [separate three-line follow-up](../../tools/engine_evaluation/forge/native-ai/empty-source/README.md)
returns null before that indexing. Four new labelled synthetic boundary checks
went from two failures/two passes to four passes; the original thirty native
checks remain unchanged and pass. No other native source changes.

The guarded profile's first built-UI attempt stopped after 46 answers because the
old frontend rejected a genuine anonymous cleanup input's empty diagnostic class
name. Its native process had not failed; the supervisor then closed the incomplete
game. This is failed qualification, not a game outcome. The UI must accept that
diagnostic label without weakening actor, generation, token or selection checks.
The earlier bcd4 game above does not qualify this final profile by implication.

## Profile Publication

The operator-only [profile builder](../../tools/engine_evaluation/forge/native-ai/runtime_profile.py)
pins the qualified base build and complete launch command. Changed JVM settings
or later overriding mounts cannot silently reuse its identity. Source/class
approval is checked before artifact reads; explicit null approval rejects.
It publishes both profile files through private descriptor-anchored staging,
file/directory fsync and a no-replace directory rename. Fifteen labelled synthetic
checks pass, including partial-write failure, parent replacement and competing
output/staging directories. These are not native games or a general hostile-host
sandbox proof. The earlier one-class profile/game above retains its historical
identity and is not relabelled as this hardened builder's execution.
