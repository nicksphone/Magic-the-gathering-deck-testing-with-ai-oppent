# Targeted Search Lifecycle Audit

Tests-only, immutable published `55ebc8c6cba982300f85289bdbe3d114fa29b2e5`.
No engine, compiler, handler, schema, AI, or existing test edits.

The whole new module executes 40 ordinary cases: 16 PASS, 24 FAIL,
34 warnings, 26.16 seconds, exit 1. No skips, expected failures, or exclusions.

## Passing Evidence

- Eight unchanged-source Fertilid controls: both seats, checked/HTTP, memory/file
  repository fixtures. Paid activation, affected-player-only private search,
  wrong-actor atomic rejection, tapped chosen basic, retained resolving controller.
- Four Fertilid's Favor episodes: both seats, selected counter target genuinely
  bounced by paid Unsummon or deliberately omitted. Search still happens; neither
  the departed hand object nor another inferred creature receives counters.
- Four hidden-hand/library identity permutations: both families, both seats,
  identical actor-private input and legal moves, unmodified original root.
- File HTTP pending snapshots reopen read-only in an independent Python process;
  state and controller roundtrip before in-process application restore. This is
  TestClient HTTP plus cold SQLite deserialization, not a separate live HTTP server.

## Strict Failures

- Eight Cloudshift episodes: the real paid response moves Fertilid to exile but
  does not return it. Reentry lifecycle is therefore unqualified, not fabricated.
- Eight Ray of Command episodes: the full canonical response is rejected as
  unsupported spell resolution. Natural control-change lifecycle is unqualified.
- Eight Unsummon episodes: actual paid bounce, search, private affected-player
  choice, restore and genuine shuffle execute. Controller and stack ID survive,
  but ordinary activated shuffle source_reference is read from the current hand
  object rather than retaining the pre-activation battlefield reference.

The source-reference failure is a requested receipt contract diagnostic, not a
claim that Magic rules mandate this internal event schema. Proposed shared seam:
capture source identity/sequence in the real activation frame and retain it through
resolution/search continuation; consume that retained reference at shuffle dispatch.
This needs separately authorized engine/frame/helper ownership. No named-card fix.
Cloudshift complete compound compilation and Ray control/delayed semantics require
separate scopes; this audit does not bypass them or certify all search lifecycles.

## Privacy And Provenance

Only the specific Fertilid publicly present on the battlefield and genuinely
returned to hand may remain known. Every other opposing hand/library card stays
unknown. The original broad privacy helper caused the preserved first-run fixture
failures and was replaced only in this new module, not in existing tests.

Full Cloudshift, Ray of Command and Unsummon JSON responses were fetched from
Scryfall's official named-card API before offline tests. The adjacent intake.txt
records URLs/timestamps; SHA256SUMS records exact unchanged response hashes.
Fertilid/Favor/basics use already verified full canonical fixtures from the pinned
source. Starting retained battlefield Fertilid with counters is explicit board
setup, not a claim of naturally casting it or of its entry compiler.
