# Jailer, Reanimate And Cathar Candidate

The candidate is a surgical increment over published `c1057647`. Four production
files change: graveyard permission queries, casting restrictions, selected-cost
admission and one existing graveyard-return handler. No compiler, raw API,
serializer, planner, payment executor, dependency or production-origin changes.

## Rules Corrections

Complete printed Soulless Jailer clauses prohibit permanent cards entering from
graveyards and noncreature spells being cast from graveyards or exile. Selected
casting-method types are queried before payment and included in the pure query
key. Legacy general-zone queries and existing prohibition precedence remain.
The three new query/admission modules have 102 cases. The existing 25-module
parent gate passed 629 cases with ten explicitly opt-in HTTP cases skipped;
those skips are not ordinary passes or complete HTTP qualification.

Reanimate's independent life-loss instruction still applies to a legal graveyard
target when battlefield entry is prohibited. Its handler retains missing-target,
reference, departed-token and all-target-fizzle checks and uses the existing
prevention-aware life-loss handler. The corrected two whole canonical modules
pass all 30 cases, including paid Cremate target departure and mana-value-eight
blocked/allowed returns. Boards and resources are seeded, not naturally earned.
The earlier 18-pass packet contained two incorrect no-life-loss expectations and
remains historical, not valid canonical qualification for those cases.

Two existing entry-block tests now independently derive a full expected snapshot
from the pre-state with only actor life minus one and the existing log entry.
Every other field remains compared without actual-result normalization. Their
48 original ordered nodes are preserved: unchanged post-fix module 46 pass/two
obsolete assertions fail; adapted whole module 48 pass.

One old countered-spell fixture now uses actual `add_to_stack` publication rather
than an untyped hand-built item. Both departure branches and all three original
assertions remain. The entire original 13-case module reproduces one failure
before this fixture correction and passes afterward. This is publication and
departure unit coverage, not a paid-cast/full-damage certificate.

## Harness Corrections

The Cathar launcher exports only its actual frontend URL as its trusted origin
before every initial startup and restart. Backend defaults, original gameplay,
selectors and deadlines are unchanged. Four actual-script startup/restart
controls pass, as do the complete original frontend test prefix plus its new
entrypoint (45 entrypoints), lint and production build with the pinned cache.

The first mounted six-scenario run passed real startup and restart checkpoints
but failed an initial `performance.timeOrigin` read before page reload; no
scenario completed. Its underlying cause was not retained and is unknown. The
same six scenarios passed with an execution-only passive, private CDP metadata
observer. That later pass does not explain the earlier failure or certify the
unobserved default full-browser flow. No driver retry or deadline change was made.

Five legacy guard canaries are now explicitly scoped by exact committed path
and original test name during their own test call. An inert preinstalled audit
hook and temporary bare-socket constructor adapters enforce their original
exceptions, revoke saved contexts and restore constructor attributes afterward.
Twenty-nine new protocol checks plus the seven original canary cases pass.
This is call-scoped compatibility, not proof of global precollection denial or
constructor-identity transparency while a canary is active. Ordinary gameplay
and CI SQL admission remain outside that scope.
