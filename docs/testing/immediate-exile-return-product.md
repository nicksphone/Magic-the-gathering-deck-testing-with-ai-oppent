## ABI And Execution

An anchored complete-body matcher runs before instruction splitting and broad
exile admission. It recognizes the exact supported creature or creature/enchantment
exile-then-immediate-return grammar, not card names. New-prefix unsupported tails
return a diagnostic noop rather than exile-only reward.

Effect key `exile_return_immediate`: explicit target_card_id, return_control
(`resolving_controller` or `owner`), requires_control, and private announced
incarnation/sequence. No omitted target inference or new public choice schema.

The executor validates the announced battlefield reference, calls the existing
exile primitive once, and retains the actual resulting exile reference plus
recipient. On entry-choice resume it validates this same exiled object; it does
not re-exile, select another target, or accept a changed sequence. Tokens cannot
return. Existing entry prohibition, day/night/land entry, static order, counter
replacement preparation/commit, sickness and ETB machinery are reused.

Fixed printed entry counter clauses are anchored per full line and sent as entry
options through prepare_counter_entries, not directly assigned after entry.
Existing count parsing is reused. Prospective ability suppression is queried on
copy-only entering-card/state projections, leaving the real root unmodified.
This supports the measured Humility case and full Fertilid entry clause without
a named exception. Arbitrary conditional/dynamic entry clauses are not certified.

The original activated search item retains its controller even when Flicker
returns the source to its foreign owner. Jason's separate shuffle-reference
receipt fix is neither edited nor claimed here. Erdos's targeted-search helper
body is byte/AST unchanged. Averroes received direct additive-hunk/ABI coordination
before edits; no self-animation/layer function is changed.
