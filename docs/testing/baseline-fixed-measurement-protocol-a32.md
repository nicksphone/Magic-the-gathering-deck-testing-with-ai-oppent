# Fixed-game producer and packager: protocol component only

This additive API is not an actual measurement, historical-baseline repair,
full matrix/BO3 qualification, or AI-strength claim. No game was played in the
component tests. The historical missing `bad_blocks` remains unavailable.

## Entry And Prerequisites

`scripts.matchup_round_robin.run_fixed_game_measurement` is an explicit opt-in
Python API, not a changed default CLI. Existing BO3/default function bodies and
the report/comparator semantics are unchanged. Required inputs include an
immutable complete canonical builtin export, exact source binding, reviewed
source partition/digest, source-bound activation control, real Oracle report,
actual agent-priors path, explicit pair/token, all 14 limits, and an externally
approved artifact charger. This code does not install a storage manager or
authorize any game, SQL, child, provider, network, or private-input operation.

The external `artifact_guard(path, byte_count)` must reserve/charge the finite
approved artifact quota BEFORE returning; rejection must raise. It is a trusted,
separately reviewed operator dependency, not supplied by this component. Merely
passing a callable is not qualification of an actual operator/storage contract.
All output files and JSONL copies call it before creation. The caller must retain
its genuine quota/ownership/closure receipts under the future execution grant.

The new producer defines `export.corpus_sha256` as the canonical digest of the
existing `oracle_corpus_report.collect_corpus()` mapping. This tightens ONLY the
new API; existing `make_export`/BO3 contracts are not reinterpreted. Full Oracle
name/copy/deck/source coverage and status aggregates must match that complete
source corpus. The Oracle file itself must come from a separately approved real
producer, not synthesized counts; unit Oracle observations here are labelled
inert protocol fixtures. The separately qualified full official card export and
provenance remain prerequisites: `ready_for_match` alone proves completeness,
not official-body authenticity.

## Source And Activation Partition

The reviewed partition has exactly `schema_version`, `arm`, `configuration`,
`controlled_files`, `features`, and `activation_control`. Its canonical digest
must equal the externally reviewed `partition_sha256`. The actual effective
configuration is recomputed, including difficulty, inferred archetypes, roster
content, full schedule/selection, actual input hashes, limits/lifetime and the
actual interpreter/prefix content digest. Unknown config changes reject.

Each feature is one of the comparator's existing six task keys and contains
finite hunks with `path`, `kind`, `qualified_name`, `reference`, and `active`.
Only `ai/` and `knowledge/` source/data can carry experimental hunks; producer,
reporter, rules/state, metric, deck and runtime code remain controlled. Python
hunks match an entire actual named function or constant AST and invert
to the approved reference AST; JSON hunks match an existing exact dotted key
and invert to the approved value. No whole-file exemption exists. Normalized
changed files plus unchanged file hashes must equal `controlled_files` exactly.
The controlled-policy digest also binds effective configuration. For an explicit
priors-data experiment only, a reviewed JSON hunk at `@configuration` /
`input_sha256.priors` may normalize the consumed digest; the SAME feature must
also contain a real `ai/data/log_priors.json` hunk. This is not a general mismatch
override. Rules, state, metrics, limits, seed/roster and runtime drift stay controlled.

`activation_control` names its real backend path and qualified function. Loaded
code must equal a compile-only traversal of that pinned source, with the actual
module globals. It is invoked, not replaced with a supplied receipt. The reviewed
control must genuinely exercise the intended feature/branch and return exactly
the observed configuration digest and feature digests. Reviewing the control's
meaning is mandatory; a constant-returning "proof" is not an activation test.
The game runner, trace builder, archetype inference, agent constructor, priors
loader and corpus collector are also checked against their actual loaded code.

## Work Unit And Evidence

The complete builtin export is validated/admitted and the complete schedule is
built BEFORE selecting exactly one approved pair/token with both physical seats.
Both mirrors are independent calls to the existing `run_game`, starting player 1,
sharing ONE `ResourceBudget` through packaging. There is no per-seat deadline or
batch reset. `begin_game` only resets the original per-game accounting. Snapshot
operations are not introduced; their boundary is explicitly unexercised.

The optional hook rides the existing `record_game` callback's `before_encode`
attribute, already forwarded by `run_game` to `_record_game_evidence`. Missing
attribute means the exact old path. The hook preflights the full result, raw log,
and exact writer envelope using bounded `checked_json`, before the original
unbounded JSON encoders/writer. It never changes outcomes. Oversize result/raw
envelopes may stop below the 4 MiB game-log ceiling; this is not a cap increase.

Only accepted full raw traces are scanned/summarized. Legacy final combined pass
runs remain distinct from per-player quality streaks. All anomalies use existing
definitions, including the legacy loop-plus-scanner missed-land contribution.
`legacy-gate.json` retains the original non-long timeout counter unchanged.
`comparison-gate.json` explicitly uses all actual tick timeouts, with long-game
timeouts a subset, as the unchanged comparator requires. Resource/action/evidence
stops and resolved draws are never relabelled tick timeouts.

JSONL `deck_a`/`deck_b` identify PHYSICAL seats 1/2. `pair_a`/`pair_b` and
`deck_a_seat` identify the canonical scheduled pair separately. Raw writer receipts,
input hashes, schedule/selection/exclusion ledger, package and source/runtime
closure are retained without a self-hash cycle. `package_measurement` reads actual
closed outputs, calls unchanged `build_report`, and validates the new receipt;
it never launches or retries a game. Missing metrics or incomplete/draw evidence
produces an ineligible diagnostic, never invented zeroes or final metrics.
